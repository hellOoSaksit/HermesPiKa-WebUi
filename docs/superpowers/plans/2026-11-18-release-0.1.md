# Release 0.1 Installer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A beginner can install hpk 0.1.0 on another machine: by double-clicking `hpk.exe`, with one install command, or with one Docker compose file. Hermes is found or installed automatically.

**Architecture:**
- A new `internal/selfinstall` package copies the running binary into `<hpk data>/bin`, registers PATH, and adds a Windows Start-menu shortcut.
- `cmd/hpk` triggers it on a no-argument start from elsewhere.
- Two install scripts download and verify a release, then call `hpk self-install`.
- The release workflow adds a bare `hpk.exe`, the scripts, and a multi-arch GHCR image of `docker/hermes`.
- Docs: English, with an identical Thai guide.

**Tech Stack:** Go (`golang.org/x/sys/windows/registry`), PowerShell 5.1, POSIX sh, GitHub Actions, goreleaser v2, docker buildx.

**Spec:** `docs/superpowers/specs/2026-11-18-release-0.1-design.md`

## Global Constraints
- Version string is `0.1.0`, tag `v0.1.0`.
- Repo: `hellOoSaksit/HermesPiKa-WebUi`. Image: `ghcr.io/hellooosaksit/hpk-hermes` (GHCR needs a lower-case name).
- Install target: `<launch.DataDir()>/bin/hpk[.exe]`. Windows: `%LOCALAPPDATA%\hpk\bin`.
- `HPK_DATA_DIR` overrides the data dir (tests). `HPK_RELEASE_BASE` overrides the download base URL in both scripts (tests).
- Scripts must verify SHA-256 against `checksums.txt` and stop on a mismatch. They download only over https, or from `HPK_RELEASE_BASE`.
- No real personal names, paths or keys. Use `C:\code\app`, `/home/me`.
- Every new source file starts with `// SPDX-License-Identifier: MIT AND LicenseRef-Commons-Clause-1.0`. In scripts, use `#` comments.
- Docs: `docs/install.md` (English) and `docs/install.th.md` (Thai) have the same headings in the same order and the same steps. Each links to the other at the top.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branch `feat/release-0.1`. Never push.

## Review Focus
1. **Double-click when hpk is already running from the install dir** (an upgrade): stop it, replace it, restart. Never a "file in use" crash. → Task 1 test.
2. **Windows PATH that already contains the dir, or is a REG_EXPAND_SZ with `%USERPROFILE%`**: no duplicate entry, and the type is kept. → Task 1 test.
3. **A user profile path with spaces or Thai characters**: the shortcut, PATH and scripts all work. → Tasks 1 and 2 tests.
4. **No internet, or a GitHub rate limit**: the script prints a clear message and exits non-zero, leaving nothing half-installed. → Task 2 test.
5. **macOS Gatekeeper quarantine** on a downloaded binary: the script removes `com.apple.quarantine` from the installed file. → Task 2 step.

### Task 1: `internal/selfinstall` + `hpk self-install` / `self-uninstall` + auto on double-click

**Files:**
- Create: `internal/selfinstall/selfinstall.go`, `selfinstall_windows.go`, `selfinstall_other.go`, `selfinstall_test.go`, `cmd/hpk/selfinstall.go`
- Modify: `cmd/hpk/main.go` (the no-argument start path, line ~59), `cmd/hpk/main.go` usage text

**Interfaces:**
- Produces:
  - `func selfinstall.Target() string` → `<DataDir>/bin/hpk(.exe)`.
  - `func selfinstall.IsInstalled(exe string) bool` → true when `exe` is the same file as `Target()` (case-insensitive on Windows).
  - `type Result struct { Copied, PathAdded, Shortcut bool; Target string }`
  - `func selfinstall.Install(exe string, out io.Writer) (Result, error)`
    - Stops a running hpk first, using the existing `launch.Runs` / stop logic that `hpk stop` uses.
    - Copies through a temp file, then renames. On Windows, if the target is busy, it renames the old file to `hpk.old.exe` first.
    - Adds PATH. Windows: HKCU Environment `Path`, keeping the REG_EXPAND_SZ type, with no duplicate (compared case-insensitively and after expanding env vars), then broadcasts `WM_SETTINGCHANGE`. Other OSes: append `export PATH="<dir>:$PATH" # added by hpk` to the existing `~/.profile`, `~/.zshrc` and `~/.bashrc`, only if the marker is absent.
    - Windows Start-menu shortcut: `%APPDATA%\Microsoft\Windows\Start Menu\Programs\HPK Console.lnk`, created via `powershell -NoProfile -Command` and WScript.Shell, with the target `Target()`.
  - `func selfinstall.Uninstall(out io.Writer) error`: the reverse. It leaves the data and the Hermes home alone.
  - CLI:
    - `hpk self-install` (exit 0 on success) and `hpk self-uninstall`.
    - When `hpk` runs with no args and `!IsInstalled(os.Executable())`, it runs Install, prints "hpk is installed for you at <target>. Starting HPK Console…", then execs the installed copy with no args and exits.
    - When the env `HPK_NO_SELFINSTALL=1` is set, or stdout is not a terminal and `--no-install` is given, it skips all of this.

### Task 2: one-command install scripts

**Files:**
- Create: `install.ps1`, `install.sh` (repo root), `tools/install-scripts.test.mjs`

**Interfaces:**
- Consumes: Task 1's `hpk self-install`.
- Produces:
  - `install.sh`:
    - POSIX sh. It detects `uname -s` / `uname -m`, mapping to `linux|darwin` and `amd64|arm64`.
    - It reads the latest version from `https://api.github.com/repos/hellOoSaksit/HermesPiKa-WebUi/releases/latest` (tag_name), or from `HPK_VERSION`.
    - It downloads `hpk_<ver>_<os>_<arch>.tar.gz` and `checksums.txt` from `${HPK_RELEASE_BASE:-https://github.com/hellOoSaksit/HermesPiKa-WebUi/releases/download/v<ver>}`, and verifies with `sha256sum` or `shasum -a 256`.
    - It extracts to a mktemp dir, removes the quarantine with `xattr -d com.apple.quarantine` on darwin (ignoring errors), runs `./hpk self-install`, then prints the next step and runs `"$target" &` unless `HPK_NO_START=1`.
    - It uses `set -eu` and a trap that cleans the temp dir.
  - `install.ps1`: PowerShell 5.1 with the same flow. Archive `hpk_<ver>_windows_<amd64|arm64>.zip`, `Get-FileHash -Algorithm SHA256`, `Expand-Archive`, `& hpk.exe self-install`, then `Start-Process` the installed hpk unless `$env:HPK_NO_START`.
  - Archive names must match goreleaser's default `{{ .ProjectName }}_{{ .Version }}_{{ .Os }}_{{ .Arch }}`. Verify this in `.goreleaser.yaml`, and set `name_template` explicitly if needed.

- [ ] **Step 1: Failing test** `tools/install-scripts.test.mjs` (node test runner). It builds a fake release dir (a tar.gz containing a stub `hpk` sh script that records its args, plus `checksums.txt`), serves it via `HPK_RELEASE_BASE=file://`, or uses a tiny local http server from node.
  - `install.sh installs and calls self-install` (skipped on win32 unless `sh` exists): the stub records `self-install`.
  - `install.sh refuses a bad checksum`: exit non-zero, and the stub was not run.
  - `install.ps1 refuses a bad checksum` (win32 only; `powershell -NoProfile -File install.ps1` with env set).
  - `no network → clear message`: base URL `http://127.0.0.1:1` → non-zero exit, and stderr contains "download".
- [ ] **Step 2:** Run `node --test tools/install-scripts.test.mjs`. Expected: FAIL.
- [ ] **Step 3:** Implement both scripts.
- [ ] **Step 4:** Run the same command. Expected: PASS. Also `sh -n install.sh`.
