# ออกแบบ: เลือกที่เก็บไฟล์ + โครงโฟลเดอร์ต่อโปรเจกต์ + ปิดระบบทีมในเวอร์ชันแรก

สถานะ: ร่าง รออนุมัติ (2026-11-18)

## 1. ทำไม

- เวอร์ชันแรกของ hpk ใช้ **คนเดียว** ระบบทีมมีโค้ดแล้ว แต่ยังไม่ควรให้คนใช้ในตอนนี้
- แต่ละโปรเจกต์เก็บไฟล์ไม่เหมือนกัน เช่น งาน 3D แยก `RAW 3D` / `Export` / `Texture` แต่ hpk ยังไม่รู้เรื่องนี้ AI จึงวางไฟล์มั่ว
- ที่เก็บไฟล์ของ hpk ตายตัว และต้องพิมพ์ path เอง ไม่มีปุ่ม Browse

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ห้ามเกิด

**เป้าหมาย**
1. AI ถามคุณครั้งเดียวต่อโปรเจกต์ว่าจะแบ่งโฟลเดอร์อะไร เก็บอะไร แล้วจดลง wiki ไม่ถามซ้ำ
2. hpk ใช้กฎนั้นใน 3 ที่: บอก AI (และเตือนเมื่อวางผิด), วางไฟล์ที่อัปโหลด, ปุ่มจัดระเบียบ
3. ปุ่ม Browse เลือกโฟลเดอร์ใน Console, ย้าย wiki ได้ต่อโปรเจกต์, เลือกที่เก็บบันทึกเบราว์เซอร์ได้
4. ฟังก์ชันทีมใน Console เป็นสีเทา + ป้าย "มาในเวอร์ชันถัดไป"
5. แผนส่วนทีมที่เหลือจดไว้ใน `docs/ROADMAP.md`

**ไม่ใช่เป้าหมาย**
- ไม่มีชุดโฟลเดอร์สำเร็จรูป (3D/วิดีโอ/เสียง ฯลฯ): ทุกโปรเจกต์ถามเอง
- ไม่ลบโค้ดทีม และไม่เปลี่ยนโหมด server ทีม (`hpk serve --team`): ปิดเฉพาะทางเข้าใน Console ของโหมดคนเดียว
- ไม่ทำหน้าต่างเลือกโฟลเดอร์ของ OS

**ห้ามเกิด**
- hpk ย้ายหรือลบไฟล์ของคุณโดยคุณไม่ได้กดยืนยัน
- AI ตั้งกฎโฟลเดอร์เอง (ข้ามการอนุมัติ)
- ที่เก็บบันทึกเบราว์เซอร์ไปอยู่ในที่ที่ AI อ่านได้ ขณะแยกบัญชี AI อยู่
- หน้า Browse ให้ AI หรือเว็บอื่นใช้ดูรายชื่อโฟลเดอร์ในเครื่อง

## 3. ทางที่พิจารณา

|---|---|---|---|---|

## 4. กฎโฟลเดอร์ใน wiki

### 4.1 รูปแบบหน้า

หน้า `decisions/folders.md` (front-matter แบบ wiki ปกติ) มีตารางที่ hpk อ่าน หัวตารางเป็นอังกฤษตายตัว:

```markdown
| Folder | What goes here | Extensions |
|---|---|---|
| RAW 3D | ไฟล์งานต้นฉบับ | .blend .max |
| Export | ไฟล์ส่งออก | .fbx .obj .glb |
| Texture | รูปพื้นผิว | .png .jpg .tga |
```

- `Folder`: path สัมพัทธ์กับโฟลเดอร์โปรเจกต์ ใช้ `/` ซ้อนได้ (`Art/Texture`) ห้าม `..`, path เต็ม หรือ link ออกนอกโปรเจกต์
- `Extensions`: คั่นด้วยช่องว่างหรือจุลภาค ไม่สนตัวพิมพ์ นามสกุลหนึ่งอยู่ได้แถวเดียว (ซ้ำ = lint เตือน, ใช้แถวแรก)
- คำว่า "ไม่แบ่งโฟลเดอร์" = หน้า wiki มีอยู่แต่ไม่มีแถวในตาราง → hpk ถือว่าตอบแล้ว ไม่ถามอีก
- ตารางเสีย (หัวไม่ตรง) → hpk ไม่ใช้กฎ, `hpk wiki lint` และ Console บอกว่าแถวไหนเสีย

### 4.2 AI ถามอย่างไร

- hook `pre_llm_call` (`session_link` เดิม) ใส่ `{"context": …}` เมื่อ session ผูกกับโปรเจกต์:
  - ยังไม่มีหน้า (ทั้งที่อนุมัติแล้วหรือร่างค้าง): "ก่อนบันทึกไฟล์ลงโปรเจกต์ครั้งแรก ให้ถามผู้ใช้ว่าจะแบ่งโฟลเดอร์อะไร เก็บอะไร แล้วร่างหน้า `decisions/folders.md` ตามรูปแบบนี้ …"
  - มีร่างค้าง: "กฎโฟลเดอร์รอผู้ใช้อนุมัติ (ร่าง #n) อย่าถามซ้ำ"
  - มีหน้าแล้ว: ตารางกฎแบบย่อ (บรรทัดละโฟลเดอร์)
- skill `hpk-wiki` เพิ่มหัวข้อ "โครงโฟลเดอร์" อธิบายเหมือนกัน (กรณี hook ไม่ทำงาน)
- ใส่ context เฉพาะครั้งแรกของ session และเมื่อหน้าเปลี่ยน (เก็บ hash ล่าสุดต่อ session) เพื่อไม่เปลือง token

### 4.3 อนุมัติ → สร้างโฟลเดอร์

- อนุมัติร่างผ่านหน้า Wiki ของ Console หรือ `hpk wiki approve` ตามเดิม (`decisions/` = คนอนุมัติเท่านั้น โหมด Auto อนุมัติไม่ได้)
- หลังอนุมัติ hpk สร้างโฟลเดอร์ที่ยังไม่มีในโปรเจกต์ (สร้างเท่านั้น ไม่ย้าย ไม่ลบ)
- **กันไม่ให้ AI ข้ามการอนุมัติ** (ผู้สร้างตัดสินใจ): AI เขียนไฟล์ใน Hermes home ได้ จึงเขียนหน้านี้ตรง ๆ ได้ ดังนั้นตอนอนุมัติ hpk จะบันทึก hash ของหน้าไว้ในที่ที่มีแต่คุณเขียนได้ (`<private>/folders/<project>.sha256` เมื่อแยกบัญชี AI) และใช้กฎเฉพาะเมื่อหน้าตรงกับ hash นั้น ถ้าไม่ตรง ถือว่ายังไม่มีกฎ และ Console แจ้งว่า "หน้ากฎถูกแก้นอกการอนุมัติ" ถ้าไม่ได้แยกบัญชี AI ให้เก็บ hash ใน `<hpk data>` แทน เป็นแค่การกันอุบัติเหตุ เพราะ AI ใช้บัญชีเดียวกับคุณ (ตรงกับข้อจำกัดที่เขียนไว้ใน docs/browser.md)

### 4.4 เตือนเมื่อ AI วางผิด

- hook `post_tool_call` ดูเครื่องมือที่เขียนไฟล์ (`write_file`, `patch` ฯลฯ ที่มี path ในอินพุต) ถ้าไฟล์อยู่ในโปรเจกต์ นามสกุลมีในกฎ และไม่ได้อยู่ในโฟลเดอร์ของมัน → `{"context": "ไฟล์ x.fbx ควรอยู่ใน Export/ ตามกฎโปรเจกต์"}`
- ไม่บล็อก ไม่ย้ายเอง ไม่ดูคำสั่ง terminal (เกินไป) ใช้งบเวลาของ hook ตามเดิม (Windows 80 ms)

## 5. อัปโหลดไฟล์

ตอนนี้แชตส่งแค่ชื่อไฟล์ ไม่มีการอัปโหลดจริง งานนี้เพิ่ม:

- `POST /api/files/upload?project=<name>` (multipart), โหมดคนเดียว + Console key
- ปลายทาง: โฟลเดอร์ตามกฎ (นามสกุล), ไม่มีกฎหรือไม่ตรง → รากโปรเจกต์
- ชื่อซ้ำ → `name (2).ext` ไม่เขียนทับ
- จำกัดขนาด: 2 GB ต่อไฟล์ (ตั้งได้ `files.upload_max`), เขียนผ่านไฟล์ชั่วคราวแล้ว rename, ปฏิเสธชื่อที่มี `..`/path/อักขระต้องห้าม, ปฏิเสธเขียนผ่าน link
- แชต: แนบไฟล์ = อัปโหลดจริง แสดงความคืบหน้า แล้วส่ง path สัมพัทธ์ให้ AI ในข้อความ; หน้า Files มีปุ่มอัปโหลด + ลากวาง
- โปรเจกต์ที่ privacy เป็น `isolated` หรือ managed `.env`: ปฏิเสธชื่อ `.env` ตามกฎ vault เดิม

## 6. ปุ่มจัดระเบียบ

- หน้า Files ของโปรเจกต์: ปุ่ม "จัดระเบียบ" → `GET /api/files/tidy?project=` คืนรายการ `{from, to, reason}`:
  - ไฟล์นามสกุลมีกฎแต่อยู่นอกโฟลเดอร์ → ย้ายเข้า
  - ไฟล์นามสกุลไม่มีกฎ → แสดงกลุ่ม "ยังไม่มีที่" (ไม่ย้าย)
- ไม่แตะ: `.git`, `node_modules`, โฟลเดอร์ที่ซ่อน, ไฟล์ที่ git ignore, ไฟล์ที่อยู่ในโฟลเดอร์ตามกฎอยู่แล้ว (แม้ซ้อนลึก)
- คุณติ๊กเลือก (ค่าเริ่มต้นเลือกทั้งหมด) → `POST /api/files/tidy` ย้ายเฉพาะที่เลือก ชื่อชนกันใช้ `name (2).ext`
- ก่อนย้ายเช็กว่าต้นทางยังเป็นไฟล์เดิม (ขนาด + เวลาแก้ไข) ไม่ตรง = ข้ามแล้วแจ้ง
- บันทึกทุกการย้ายใน `audit.log` ของโปรเจกต์ และมีปุ่ม "ย้อนกลับ" ของรอบล่าสุด (ผู้สร้างตัดสินใจ): เก็บรอบล่าสุดของแต่ละโปรเจกต์เป็นไฟล์ `tidy-last.json` ข้างไฟล์ `project.yaml` ซึ่งยังอยู่หลัง restart ไฟล์ไหนถูกแก้หลังย้าย (ขนาดหรือเวลาแก้ไขไม่ตรง) จะข้ามแล้วแจ้ง ไฟล์ที่ย้ายด้วย `git mv` จะย้อนด้วย `git mv` เหมือนกัน แต่ไม่ commit
- ไฟล์ที่ git ติดตามอยู่: ย้ายด้วย `git mv` เพื่อให้ประวัติไม่หาย

## 7. Browse เลือกโฟลเดอร์

- `GET /api/fs/dirs?path=` คืนรายการ **โฟลเดอร์เท่านั้น** (ไม่มีไฟล์) + โฟลเดอร์แม่ + ทางลัด (Home, Documents, Desktop, ไดรฟ์บน Windows)
- โหมดคนเดียวเท่านั้น, ต้องมี Console key **แม้เป็น GET**, Host loopback ตามเดิม, hook ของ AI บล็อก (`/api/` ของ Console ถูกบล็อกอยู่แล้ว)
- ไม่ตาม link ออกไปนอกที่แสดง, ซ่อนโฟลเดอร์ระบบ (Windows, Program Files, `/proc` ฯลฯ) และโฟลเดอร์ private ของ hpk
- ปุ่มใน Console: component `pickFolder()` ใช้ใน wizard สร้างโปรเจกต์, เปลี่ยนโฟลเดอร์โปรเจกต์, ย้าย wiki, ที่เก็บบันทึกเบราว์เซอร์ ช่องพิมพ์ path เดิมยังอยู่

## 8. ที่เก็บต่าง ๆ

| อะไร | ค่าเดิม | เปลี่ยนได้ที่ | กติกา |
|---|---|---|---|
| โฟลเดอร์โปรเจกต์ (`root`) | ตามที่เลือกตอนสร้าง | Settings ของโปรเจกต์ | เปลี่ยนแค่ path (ไม่ย้ายไฟล์ให้), โฟลเดอร์ต้องมีอยู่; แยกบัญชี AI อยู่ → hpk ให้สิทธิ์ `hpk-ai` ที่โฟลเดอร์ใหม่และถอนจากที่เก่า |
| wiki ของโปรเจกต์ | `hermes/hpk/projects/<ชื่อ>/wiki` | Settings ของโปรเจกต์ | **ย้ายจริง** (git ของ wiki ย้ายไปด้วย) ไปโฟลเดอร์ว่างหรือที่ยังไม่มีอยู่; `WikiDir()` อ่านที่อยู่ใหม่จาก `<hpk data>/wikis.json` ซึ่งมีแต่คุณเขียนได้ (ถ้าเก็บใน `project.yaml` AI จะชี้ไปที่ wiki ของมันเองได้); ถ้าแยกบัญชี AI อยู่ จะให้สิทธิ์ `hpk-ai` ที่ใหม่ ถอนสิทธิ์จากที่เก่า และอัปเดต `Granted` ใน `isolation.json` |
| บันทึกเบราว์เซอร์ | โฟลเดอร์ private (`browser/runs`) | Settings > Browser | ย้ายจริง; แยกบัญชี AI อยู่ → ปฏิเสธที่อยู่ใน Hermes home, โฟลเดอร์โปรเจกต์ใด ๆ หรือที่ที่ `hpk-ai` อ่านได้ และตั้งสิทธิ์ใหม่เป็นคุณ + SYSTEM; เก็บใน `isolation.json` (ไม่ใช่ใน home ที่แชร์) หรือ `<hpk data>/settings.json` เมื่อไม่ได้แยก; profile เบราว์เซอร์ไม่ย้าย |

**บันทึกเบราว์เซอร์กับการเปิดหรือปิดการแยกบัญชี AI** (ผู้สร้างตัดสินใจ): ตอน `hpk isolate setup` ถ้าที่เก็บที่เลือกไว้เป็นที่ที่ `hpk-ai` จะอ่านได้ (เช่น อยู่ใน Hermes home หรือในโฟลเดอร์โปรเจกต์) setup จะย้ายบันทึกเข้าโฟลเดอร์ private แล้วรีเซ็ตเป็นค่าเริ่มต้น โดยแสดงเป็นขั้นหนึ่งในแผนก่อนให้คุณยืนยัน ถ้าเป็นที่อื่น จะเก็บไว้ที่เดิมแล้วตั้งสิทธิ์ใหม่ ตอน teardown บันทึกจะอยู่ที่เดิมถ้าคุณเคยเลือกที่เก็บเอง ถ้าใช้ค่าเริ่มต้นจะกลับไป `browser/runs` ตามเดิม

การย้าย (wiki, บันทึก): คัดลอก → ตรวจครบ → สลับ path → ลบที่เก่า; ล้มกลางทาง = ที่เก่ายังอยู่ครบ; ทำได้เมื่อไม่มีงานที่ใช้อยู่ (wiki: ไม่มี ingest/cron ของโปรเจกต์กำลังรัน; บันทึก: เบราว์เซอร์ปิดอยู่)

## 9. ปิดระบบทีมใน Console (โหมดคนเดียว)

- flag เดียว `features.team` (ค่าเริ่มต้น `false` ในเวอร์ชันนี้) ส่งมากับ `/api/bootstrap`
- เมื่อ `false`:
  - เมนู Team และ Team server: แสดงเป็นสีเทา กดไม่ได้ มีป้าย "มาในเวอร์ชันถัดไป" (tooltip `data-tip`)
  - wizard: ตัวเลือก "ทีม" สีเทา ค่าเริ่มต้นเป็น "ส่วนตัว"
  - รายการโปรเจกต์: หัวข้อ "ทีม" ซ่อนถ้าไม่มีโปรเจกต์ทีม; มีอยู่แล้ว = แสดงตามเดิม (ไม่ซ่อนงานเดิม)
  - เข้า `#/team` / `#/teamserver` ตรง ๆ → หน้าบอกว่ามาในเวอร์ชันถัดไป
  - API ฝั่ง team ในโหมดคนเดียว (ผู้สร้างตัดสินใจ): การเข้าร่วมใหม่ (`/api/join`, `/api/teamserver/join`, `/api/team/*` ที่ใช้สร้างรหัสหรือจัดการอุปกรณ์) ตอบ 404 พร้อมข้อความเดียวกัน แต่เครื่องที่เข้าร่วม server ไว้แล้วยังใช้ `/api/teamserver/leave` และ `/api/teamserver/remote/*` ได้ตามเดิม (ไม่ตัดงานเดิม) และหน้า Team server แสดงแค่สถานะกับปุ่มออกจาก server
- `hpk serve --team` (server ทีม) ไม่เปลี่ยน; เปิดกลับได้ด้วย `HPK_FEATURES=team` สำหรับทดสอบ

## 10. ROADMAP

`docs/ROADMAP.md`: รายการเดียวของส่วนทีมที่ยังไม่ทำ อ้างไปแผนละเอียด
- Connected mode (`docs/plans/connected-mode.md`): project link, outbox + `hpk sync`, รายงาน/ร่าง wiki ขึ้นทีม, กฎทีมลงเครื่อง, `team_approval`, relay บัญชี AI ทีม, Console สองฝั่ง

- OIDC/passkey ใน hpk, isolate อัตโนมัติบน macOS/Linux
- เปิด `features.team` กลับเมื่อพร้อม

## 11. ทดสอบ

- unit: อ่านตาราง (หัวเสีย, ซ้ำ, `..`, ว่าง = ไม่แบ่ง), ปลายทางอัปโหลด, tidy plan (git ignore, ซ้อนลึก, ชื่อชน, ต้นทางเปลี่ยน), dirs API (ไม่มีไฟล์, ไม่มี private, ต้องมี key), ย้าย wiki/บันทึก (ล้มกลางทาง), hook context (ครั้งแรก/hash เปลี่ยน) และเวลา hook
- Console: เทสต์ node ของ parser ฝั่งหน้าเว็บ (ถ้ามี), ลองในเบราว์เซอร์: Browse, อัปโหลด, จัดระเบียบ, เมนูทีมสีเทา
- จริงกับ Hermes: AI ถามโครงโฟลเดอร์ → ร่าง → อนุมัติ → โฟลเดอร์ถูกสร้าง → AI บันทึก .fbx ลง Export
