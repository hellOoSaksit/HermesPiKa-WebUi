# แผน: ทำงานบนเครื่องตัวเอง ต่อกับ server ของทีม (connected mode)

สถานะ: **แผน** — ส่วน 12 (แยก server, รหัสเชิญ, device token) ทำแล้ว; ส่วนอื่นยังไม่เขียนโค้ด

## 1. ภาพรวม

hpk ติดตั้งสองที่: **เครื่องของแต่ละคน** (ทำงานส่วนตัว) และ **server ของทีม** (โหมดทีม, docs/team.md)
แบบ B: Hermes รันบนเครื่องตัวเอง ใช้โค้ดบนเครื่อง แต่โปรเจคที่ "ผูก" กับโปรเจคทีมจะส่งเฉพาะสิ่งที่ทีมต้องรู้ขึ้น server

```
เครื่องฉัน                                   server ทีม (hpk serve โหมดทีม)
┌──────────────────────────┐   HTTPS + token  ┌─────────────────────────────┐
│ Hermes + hpk hooks        │ ───────────────▶ │ บอร์ด (claim, heartbeat)    │
│ โปรเจคส่วนตัว (ไม่ผูก)     │  outbox (คิว)    │ รายงาน, ร่าง wiki ทีม        │
│ โปรเจคที่ผูกกับทีม          │ ◀─────────────── │ เส้นแดง/โหมดของทีม, wiki ทีม │
│   wiki ทีม (สำเนาอ่าน)     │   pull           │ อนุมัติ, audit, งบ            │
└──────────────────────────┘                  │ (ตัวเลือก) relay บัญชี AI ทีม │
                                               └─────────────────────────────┘
```

## 2. สิ่งที่ตกลงแล้ว

| เรื่อง | ข้อตกลง |
|---|---|
| รูปแบบ | B: เครื่องตัวเองทำงาน, server เป็นศูนย์กลางของทีม |
| ผูกโปรเจค | `hpk server login` + `hpk project link` (ส่วน 4) |
| เส้นแดงขัดกัน | **เข้มกว่าชนะเสมอ**: ทีมสั่งให้ถาม เครื่องปิดไม่ได้; เครื่องเพิ่มเส้นแดงเองได้ |
| งบเงิน | งานที่ใช้คีย์ของตัวเอง: **รายงานยอดขึ้น server ให้เห็น ไม่บังคับ**; งานที่ใช้บัญชี AI ทีม: **บังคับงบทีม/งบคน** ที่ server (ส่วน 7) |
| บัญชี AI ทีม | ทาง 1: relay ผ่าน server; **ใช้กับงานส่วนตัวได้ ถ้าทีมเปิด** (ค่าเริ่มต้นปิด, งบส่วนตัวแยก, override รายคน) |
| อนุมัติเส้นแดง | ค่าเริ่มต้น: คุณอนุมัติเองบนเครื่อง และ server ได้บันทึก audit; ทีมเลือกได้ว่าเส้นแดงไหน "ต้องให้ทีมอนุมัติ" (ส่วน 6) |

## 3. อะไรขึ้น server / อะไรไม่ขึ้น

| ขึ้น server (เฉพาะโปรเจคที่ผูก) | ไม่ขึ้นเลย |
|---|---|
| claim บนบอร์ด, heartbeat, ปล่อยงาน | ข้อความแชท, transcript |
| รายงานสรุปตอนงานจบ (≤15 บรรทัด) | ไฟล์และโค้ด (ไปทาง git ตามปกติ) |
| ร่าง wiki → wiki ทีม (คนอนุมัติบน server) | คีย์ AI, `.env` |
| การตัดสินเส้นแดง (ใคร อะไร เมื่อไร) | โปรเจคที่ไม่ผูก, โปรเจค private/isolated |
| ยอด token/เงิน ต่อ session (ตัวเลข) | wiki ส่วนตัว, raw notes |

กติกา: **private/isolated ผูกกับทีมไม่ได้** (ไม่มีอะไรออกนอกเครื่องอยู่แล้ว)

## 4. ตัวตนและการผูก

```bash
# เข้าร่วม server: Settings > Team server (รหัสเชิญ, ส่วน 12) — แทน hpk server login
hpk project link harbor-api --server team --as harbor-api   # โปรเจคบนเครื่อง ↔ โปรเจคทีม
hpk project unlink harbor-api
hpk server status                                    # ต่อได้ไหม, คิวค้างกี่รายการ
```

- token เก็บที่ `<hermes home>/hpk/servers.json` สิทธิ์ 600 (Windows: ACL เจ้าของคนเดียว) — ไม่ลง log ไม่ส่งให้ Hermes
- ต่อ server ได้เฉพาะ **HTTPS** (ยกเว้น `localhost` สำหรับทดสอบ); ตรวจใบรับรองตามปกติ
- server ตรวจ: token ใช้ได้, คนนั้นมีสิทธิ์ในโปรเจคนั้น (`team.yaml` projects), บทบาทพอสำหรับสิ่งที่ส่ง
- `project.yaml` บนเครื่องเพิ่ม `team: { server: team, project: harbor-api }`

## 5. การส่งข้อมูล (sync)

**Outbox บนเครื่อง** (`hpk/outbox.db`): hook ไม่ยิงเครือข่ายเอง (hook มีเวลา 15 วินาที และต้องเร็ว) — เขียนลงคิวแล้ว `hpk serve` (หรือ `hpk sync` ที่ cron/บริการรัน) ส่งให้
- ส่งตามลำดับ, ซ้ำได้โดยไม่ซ้อน (แต่ละรายการมี id), ออฟไลน์ ⇒ ค้างในคิว แล้วส่งเมื่อต่อได้
- server เก็บว่า "มาจากเครื่องไหน ของใคร" ทุกรายการ

**กันงานซ้ำ (สำคัญที่สุด)**: ก่อนจอง claim ในโปรเจคที่ผูก hpk ถาม server ก่อน
- ต่อได้ ⇒ ตรวจชนกับคนอื่นจริง (🔴/🟠/🟡 เหมือนบอร์ดเดิม)
- ต่อไม่ได้ ⇒ จองบนเครื่อง + แจ้ง "ยังไม่ได้ตรวจกับทีม" + ส่งเมื่อต่อได้; ถ้าชนจะเตือนทั้งสองฝั่ง

**ดึงลง (pull)** ทุก 5 นาทีและตอนเริ่มแชท: เส้นแดง/โหมดของทีม, ผู้ใช้ที่ถือ claim, สำเนา wiki ทีม (อ่านอย่างเดียว ใน `hpk/projects/<p>/team-wiki/`)

## 6. เส้นแดงและการอนุมัติ

- เส้นแดงที่มีผล = เส้นแดงบนเครื่อง ∪ เส้นแดงของทีม (เข้มกว่าชนะ); โหมดที่มีผล = โหมดที่เข้มกว่า (Manual > Ask > Auto)
- ค่าเริ่มต้น: Hermes บนเครื่องถาม **คุณ** ตามปกติ, ผลการตัดสินขึ้น audit ของทีม
- ทีมตั้งได้ใน `project.yaml` ของ server: `gates.team_approval: [push, delete]` ⇒ เส้นแดงพวกนี้ต้อง **maintainer/owner บน server** อนุมัติ:
  1. guard บนเครื่องปฏิเสธพร้อมข้อความ "ส่งขออนุมัติทีมแล้ว (#42)" และสร้างคำขอบน server
  2. คนอนุมัติใน Console ของ server
  3. ผลถูกดึงลงมา เป็น "สิทธิ์ใช้ครั้งเดียว" สำหรับคำสั่งนั้น ภายใน 1 ชม.; agent ลองใหม่แล้วผ่าน
  (hook รอนานไม่ได้ จึงใช้วิธีปฏิเสธแล้วลองใหม่แทนการค้างรอ)

## 7. ใช้บัญชี AI ของทีม

เป้าหมาย: สมาชิกใช้บัญชี AI ที่ทีมจ่าย **โดยคีย์ไม่ออกจาก server** และงบทีม/งบคนใช้ได้จริง

### ทาง 1 (แนะนำ): relay ผ่าน server → subscription proxy ของ Hermes

```
Hermes บนเครื่อง ──(token hpk ของฉัน)──▶ hpk serve /model/v1 ──▶ hermes proxy (127.0.0.1 บน server) ──▶ ผู้ให้บริการ
                                          ตรวจคน+งบ, บันทึกยอด      แนบ credential จริงเอง
```

- บน server: `hermes proxy start` (ฟังเฉพาะ 127.0.0.1) — Hermes แนบ credential เอง **hpk ไม่เห็นคีย์**
- hpk serve เปิด `/model/v1/*` เฉพาะโหมดทีม + HTTPS: ตรวจ token สมาชิก, ตรวจงบคน/งบโปรเจคก่อนส่ง, อ่าน `usage` จากคำตอบแล้วบันทึกยอดต่อคน, จำกัดอัตรา (rate limit)
- บนเครื่อง: `hpk server use-team-models` เพิ่ม profile ของ Hermes ชื่อ `team` ที่ `provider: custom`, `base_url: https://team…/model/v1`, คีย์ = token hpk ของฉัน (ไม่ใช่คีย์ผู้ให้บริการ; ถอนได้ที่ Team page)
- แยกเส้นทางตามการใช้งาน เพื่อให้ server รู้ว่าเป็นงานทีมหรืองานส่วนตัว (เนื้อหา prompt ไม่ต้องเปิดดู):
  - `/model/team/v1` — โปรเจคที่ผูกกับทีม; นับเข้างบโปรเจคทีม + งบคน
  - `/model/personal/v1` — งานส่วนตัว (โปรเจคที่ไม่ผูก); ใช้ได้เฉพาะเมื่อทีมอนุญาต
  - บนเครื่องมี provider 2 ตัวใน profile `team` (`team-work`, `team-personal`); guard ตรวจว่าโปรเจคที่ผูกใช้ `team-work` และโปรเจคที่ไม่ผูกใช้ `team-personal` (สลับกันไม่ได้)

#### ใช้บัญชีบริษัทกับงานส่วนตัว — ตั้งค่าได้

ตั้งที่ `team.yaml` บน server (owner แก้ใน Team page หรือ `hpk team models …`):

```yaml
models:
  personal_use: allowed        # off (ค่าเริ่มต้น) | allowed
  personal_daily_usd: 2        # งบงานส่วนตัวต่อคนต่อวัน (0 = ไม่จำกัด)
  personal_monthly_usd: 20
members:
  - id: max@example.com
    personal_use: off          # override รายคน (ปิด/เปิด, หรือใส่งบของคนนั้นเอง)
    personal_daily_usd: 5
```

- งานส่วนตัวมีงบแยกจากงานทีม: ใช้งานส่วนตัวหมดงบส่วนตัว ไม่กระทบงานทีม และกลับกัน
- Team page แสดงยอด "งานทีม / งานส่วนตัว" แยกกันต่อคน
- ข้อความเตือนตอนเปิด: เนื้อหาของงานส่วนตัวจะผ่าน server ของบริษัท (ไม่ถูกบันทึก แต่ผ่าน) — คนที่ไม่ต้องการก็ไม่ต้องตั้ง provider `team-personal` บนเครื่อง
- โปรเจค `private`/`isolated` และ `local_only`: กติกาเดิมชนะเสมอ — `local_only` ไม่ใช้บัญชีทีมไม่ว่ากรณีใด, `isolated` ไม่ส่งเนื้อหาออกเครื่อง ⇒ ใช้ relay ไม่ได้; `private` ใช้ได้เฉพาะเมื่อเจ้าของเครื่องเปิดเอง (`privacy.allow_team_models: true` ในโปรเจคนั้น)
- **ข้อจำกัด**: proxy ของ Hermes v0.23.1 รองรับแค่ **Nous Portal และ xAI** (บัญชีแบบ OAuth) ยังไม่รองรับคีย์ Anthropic/OpenRouter ใน pool

### ทาง 2: คีย์จำกัดวงเงินต่อคน (สำหรับผู้ให้บริการที่ proxy ยังไม่รองรับ)

- owner สร้างคีย์ย่อยที่ผู้ให้บริการ (เช่น OpenRouter มีคีย์ที่ตั้งวงเงินได้, Anthropic ใช้ workspace) แล้วมอบให้แต่ละคน
- คีย์ย่อยไปอยู่ใน Hermes บนเครื่องคนนั้น (`hermes auth add`) — **คีย์ออกจาก server** แต่จำกัดวงเงินและถอนได้รายคน
- hpk บันทึกแค่ว่า "ใครถือคีย์ย่อยป้ายไหน" และรายงานยอด; ไม่เก็บตัวคีย์

### ที่ไม่ทำ

- **hpk เก็บคีย์ของทีมแล้วยิงเอง**: ขัดหลัก "hpk ไม่เห็นคีย์ ไม่เรียก LLM เอง"
- เปิด proxy ของ Hermes ออกเครือข่ายตรงๆ: proxy รับ bearer อะไรก็ได้ ใครเข้าถึงก็ใช้เงินทีมได้

## 8. Console

- เครื่องตัวเอง: แถบ "ทีม: harbor-api @ team.example.com — ต่ออยู่ / คิวค้าง 3" ในโปรเจคที่ผูก; บอร์ดแสดง claim ของคนอื่นจากทีม; หน้า wiki มีแท็บ "wiki ทีม" (อ่านอย่างเดียว)
- server: บอร์ดแสดงว่างานไหนทำบนเครื่องใคร; Team page แสดงเครื่องที่ต่ออยู่ (ล่าสุดเมื่อไร) และยอดใช้บัญชีทีมต่อคน; ปุ่ม "ถอนสิทธิ์เครื่องนี้"

## 9. ความปลอดภัย

- ทุกอย่างระหว่างเครื่อง ↔ server ผ่าน HTTPS + token ส่วนตัว; server จำกัดตาม `team.yaml` (บทบาท, โปรเจค)
- server ไม่เชื่อข้อมูลจากเครื่องแบบไม่ตรวจ: claim ผูกกับ token ผู้ส่ง, ห้ามส่งในนามคนอื่น, จำกัดขนาด/อัตรา
- token ถอนได้ทันที (`hpk team token` ออกใหม่ / remove) ⇒ เครื่องนั้นหยุด sync และหยุดใช้บัญชีทีม
- relay บัญชีทีม: ไม่บันทึกเนื้อหา prompt/คำตอบ บันทึกเฉพาะยอดและเวลา

## 10. ลำดับงาน

| ขั้น | งาน | ทดสอบ |
|---|---|---|
| 0 | ตรวจกับ Hermes จริง: `hermes proxy` หลัง hpk relay, profile แบบ custom + base_url, การอ่าน usage จาก stream | Docker (`hpk-hermes`) |
| 1 | `hpk server login/status`, `servers.json`, API ฝั่ง server `/api/remote/hello` | unit + Docker |
| 2 | `project link/unlink`, outbox + `hpk sync`, ส่ง claim/heartbeat/release, ตรวจชนกับทีมก่อนจอง | 2 container: server + "เครื่อง" |
| 3 | รายงาน + ร่าง wiki ขึ้นทีม, ดึง wiki ทีม/เส้นแดง/โหมด (เข้มกว่าชนะ) | เหมือนขั้น 2 |
| 4 | อนุมัติโดยทีม (`team_approval`), สิทธิ์ใช้ครั้งเดียว | Console server + guard บนเครื่อง |
| 5 | relay บัญชี AI ทีม (ทาง 1) + งบ/อัตรา + `use-team-models` + เส้นทาง team/personal + ตั้งค่าใช้ส่วนตัว (`models.personal_use`, งบส่วนตัว, รายคน) | Docker + บัญชีทดสอบ (ต้องมีบัญชี Nous/xAI) |
| 6 | Console ทั้งสองฝั่ง, เอกสาร `docs/connected.md` | เบราว์เซอร์ |

ขั้น 0–4 ไม่ต้องใช้โมเดลหรือบัญชี AI; ขั้น 5 ต้องมีบัญชีจริงของทีมสำหรับทดสอบ

## 11. คำถามที่ยังเปิด

1. บัญชี AI ของทีมเป็นผู้ให้บริการไหน — เลือกทาง 1 แล้ว (relay); ถ้าบัญชีเป็น Anthropic/OpenRouter ทาง 1 ยังใช้ไม่ได้กับ Hermes v0.23.1 (proxy รองรับ Nous/xAI) ต้องใช้ทาง 2 กับผู้ให้บริการนั้นไปก่อน
4. ~~งานส่วนตัวใช้บัญชีทีมได้ไหม~~ — ตกลงแล้ว: ได้ ตั้งค่าได้ (ค่าเริ่มต้นปิด, งบแยก, override รายคน)
2. ใช้ `team_approval` เส้นไหนเป็นค่าเริ่มต้น — แนะนำ: ไม่มี (ทีมเลือกเอง)
3. เครื่องหนึ่งต่อได้หลาย server ไหม — แนะนำ: ได้ (ผูกต่อโปรเจค) แต่ทำ server เดียวก่อน

## 12. แยก server ทีมออกจากเครื่องตัวเอง + เข้าร่วมด้วยรหัสเชิญ (ตกลงแล้ว, กำลังทำ)

สถานะ: **ทำแล้วรอบแรก** (ขั้น 1 ของส่วน 10 แบบใหม่) — แทน `hpk server login` ที่ต้องวาง token ส่วนตัว

### 12.1 สองบทบาท

| | server ทีม | เครื่องของแต่ละคน |
|---|---|---|
| ติดตั้ง | Docker (`docker/`), `hpk serve` โหมดทีม, ไม่มีหน้าจอบนเครื่อง (headless) | `hpk serve` แบบ solo (loopback) |

```
       → รหัส ABCD-EFGH ใช้ได้ครั้งเดียว หมดอายุ 15 นาที
max:   Console บนเครื่อง > Settings > Team server: URL + รหัส + ชื่อเครื่อง
       → hpk บนเครื่อง POST https://team…/api/join {code, device}
       → server ตรวจรหัส (เก็บแค่ SHA-256), ทิ้งรหัส, ออก device token `hpkd_…` (แสดงครั้งเดียว ให้เครื่องนั้น)
       → hpk บนเครื่องเก็บ token ใน vault (ชนิด system: ไม่อยู่ในรายการ vault, AI อ้างชื่อไม่ได้, กรอกลงเว็บไม่ได้, เปิดดูไม่ได้)
```

- คนหนึ่งมีหลายเครื่องได้ แต่ละเครื่องมี token ของตัวเอง ถอนแยกกันได้
- server เก็บที่ `<home>/hpk/devices.json` (0600): รหัสเชิญ (SHA-256, ของใคร, หมดอายุ) และเครื่อง (id, เจ้าของ, ชื่อ, token SHA-256, เพิ่มเมื่อ, เห็นล่าสุด, IP ล่าสุด)
- `/api/join` ไม่ต้อง sign-in แต่: ต้องมาทาง HTTPS (ยกเว้น loopback สำหรับทดสอบ), ผ่าน IP allowlist, ช้าลง 0.5 วิ ทุกครั้งที่ผิด, ผิดเกิน 10 ครั้งใน 10 นาทีจาก IP เดียว ⇒ ปิดชั่วคราว
- รหัสผูกกับ member ที่มีอยู่แล้ว (owner เพิ่มคนก่อน แล้วออกรหัส); ลบคนออก ⇒ เครื่องทั้งหมดของคนนั้นใช้ไม่ได้ทันที
- ไฟล์บนเครื่อง `<home>/hpk/teamserver.json`: URL, ใครที่ server, บทบาท, id/ชื่อเครื่อง — **ไม่มี token**

### 12.3 ความปลอดภัย

- TLS บังคับ: server ฟังนอก loopback ได้เฉพาะ `--tls-cert/--tls-key` หรือหลัง proxy (เดิม); ฝั่งเครื่องยอมเฉพาะ URL `https://` (ยกเว้น `localhost`/`127.0.0.1` สำหรับทดสอบ) และตรวจใบรับรองตามปกติ
- IP allowlist (ตัวเลือก): `team.yaml` → `allow_ips: [203.0.113.0/24, 198.51.100.7]` ทุกคำขอจากนอกรายการ ⇒ 403; loopback ผ่านเสมอ; หลัง proxy ที่อยู่ใน `trusted_proxies` ใช้ IP จาก `X-Forwarded-For` (ตัวขวาสุด)
- รายการเครื่อง + เห็นล่าสุด + ปุ่มถอน: owner เห็นทุกเครื่องใน Team page ของ server; แต่ละคนเห็นและถอนเครื่องของตัวเองใน Settings > Team server บนเครื่อง
- ออกจากทีม (Leave) บนเครื่อง: ถอนเครื่องนี้ที่ server (ถ้าต่อได้) แล้วลบ token จาก vault; ต้องใส่ PIN ของ vault ถ้าตั้งไว้

### 12.4 Console

- เครื่องตัวเอง: Settings > **Team server** — ยังไม่ต่อ: ฟอร์ม URL/รหัส/ชื่อเครื่อง; ต่อแล้ว: สถานะ, บทบาท, แผงทีม (คน, โปรเจคทีม + งานบนบอร์ด, คำขออนุมัติ), เครื่องของฉัน (ถอนได้), owner ออกรหัสเชิญจากที่นี่ได้ (ผ่าน proxy ของ hpk บนเครื่อง ซึ่งยอมเฉพาะเส้นทางที่กำหนด)
- hpk บนเครื่องเป็นตัวกลาง (`/api/teamserver/...`): หน้าเว็บบนเครื่องไม่เห็น token, เรียก server ได้เฉพาะเส้นทางในรายการ
- server: ซ่อนแท็บ Browser/Vault และปุ่มเบราว์เซอร์; Team page เพิ่ม "รหัสเชิญ" ต่อคน และตารางเครื่องทั้งหมด
